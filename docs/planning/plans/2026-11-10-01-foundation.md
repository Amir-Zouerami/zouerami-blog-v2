# Foundation Implementation Plan (Plan 1 of 8)


**Goal:** A running skeleton: Astro + React 19 + Tailwind on Bun, PocketBase with the content schema and seed data, nginx in front, all started by one Compose command, with a typed, zod-validated data layer that returns only published posts, plus lint, tests and CI.

**Architecture:** `web/` (Astro, server-rendered, Node adapter) talks to `pocketbase/` over the Compose network through a small typed data layer (`web/src/lib`). nginx is the only public entrypoint; it proxies `/` to web and `/pb/` to PocketBase. Access rules live in PocketBase migrations; zod validates every response.

**Tech Stack:** Bun (package manager/scripts), Node 22 LTS (runtime image), Astro + `@astrojs/node` + `@astrojs/react` (React 19, React Compiler), Tailwind v4, TypeScript strict, zod, PocketBase JS SDK, Biome, Vitest, Playwright, Docker Compose, nginx.

**Spec:** `docs/planning/specs/2026-11-10-zouerami-blog-v2-design.md`

## Global Constraints
- Package manager is Bun; production image runs **Node** (not Bun). Pin every dependency and image version exactly and record them in `docs/versions.md` (executor looks up current stable; do not guess).
- TypeScript `strict: true`. No `any` in `web/src/lib`.
- Languages are exactly `'en' | 'fa'`. Post statuses are exactly `'draft' | 'published'`.
- Public (unauthenticated) API access may only ever read published content; create/update/delete on content collections are superuser-only.
- Slugs match `^[a-z0-9]+(?:-[a-z0-9]+)*$`.
- Git commits: end with the attribution lines required by the session; commit only when the task says so.

## Review Focus
- PocketBase unreachable → data-layer calls throw a typed `UpstreamError`; the index page renders a friendly error with HTTP 503, never an unhandled crash.
- A draft post must never appear for anonymous callers, directly by slug or in lists (test against real PocketBase rules, not only the data layer).
- Unknown slug → `getPost` returns `null` (page layer will map to 404), never throws.
- A post that has only a Persian translation lists with `langs: ['fa']`, `titleLang: 'fa'`, and its Persian title.
- Malformed PocketBase payloads (missing field, wrong type, unknown lang) are rejected by zod with a clear error naming the field.
- Missing/empty required env var fails the build/boot immediately with the variable's name in the message.
